# Data Model: IT Knowledge Graph Ingestion Pipeline

**Feature**: Epic 1 — Platform Foundation
**Date**: 2026-06-12
**Database**: SQLite 3.35+ (`data/cmdb.db`, WAL mode)

---

## Entity Overview

The schema models CMDB applications and their relationships as a graph:
- **Nodes**: `applications`, `application_types`, `architecture_types`, `business_processes`, `companies`
- **Edges**: `app_uses_type`, `app_has_architecture`, `app_supports_process`
- **ETL state**: `etl_runs`

The edge tables are the foundation for the networkx graph loaded at startup. All node entities have UUID primary keys for stability across re-ingestions.

---

## Entities

### applications

The central node. One row per CMDB application record.

| Column | Type | Nullable | Description |
|--------|------|----------|-------------|
| `application_id` | TEXT PK | No | UUID v4, stable across re-ingests (key: name + company) |
| `application_name` | TEXT NOT NULL | No | Application name from CMDB |
| `company` | TEXT | Yes | Baptist Health entity (e.g., "Baptist Hospital", "BHMG") |
| `publisher` | TEXT | Yes | Software vendor / publisher name |
| `description` | TEXT | Yes | Application description from CMDB |
| `updated` | TEXT | Yes | Last update date (ISO 8601 string) |
| `last_updated_by` | TEXT | Yes | Name of person who last updated the CMDB record (PII) |
| `business_owner` | TEXT | Yes | Business Owner name (PII) |
| `td_app_owner` | TEXT | Yes | T&D Application Owner name (PII) |
| `primary_engineer` | TEXT | Yes | Primary Engineer name (PII) |
| `support_group` | TEXT | Yes | Application Support Group name |
| `active` | INTEGER | Yes | Active flag from CMDB (1=active, 0=inactive) |
| `install_status` | TEXT | Yes | Installation status |
| `application_url` | TEXT | Yes | URL of the application |
| `portfolio_manager` | TEXT | Yes | Application Portfolio Manager name |
| `application_type` | TEXT | Yes | Normalized: `'COTS'` \| `'Homegrown'` \| NULL |
| `architecture_type` | TEXT | Yes | Deployment pattern (raw value from CMDB) |
| `baptist_managed` | INTEGER | Yes | 1=Baptist-managed, 0=vendor-managed, NULL=unspecified |
| `business_criticality` | TEXT | Yes | Business criticality rating |
| `business_process` | TEXT | Yes | Primary business process (raw value; may be multi-value in source) |
| `environment` | TEXT | Yes | Deployment environment |
| `active_status` | INTEGER NOT NULL | No | 1=active in platform, 0=soft-deleted on refresh. Default 1. |
| `content_hash` | TEXT | Yes | SHA-256 of `application_name + description` — used for incremental re-embedding (Epic 3) |

**Notes**:
- PII columns (last_updated_by, business_owner, td_app_owner, primary_engineer) are stored here and displayed in the UI detail panel. They must NOT be used in `build_embed_payload()` or OpenAI API calls.
- `active_status = 0` records are soft-deleted; excluded from all default queries.
- `application_type` is normalized on ingest; the raw source value is not stored.

### application_types

Reference table for normalized application type values.

| Column | Type | Nullable | Description |
|--------|------|----------|-------------|
| `type_id` | TEXT PK | No | UUID v4 |
| `type_name` | TEXT NOT NULL UNIQUE | No | `'COTS'` or `'Homegrown'` |

**Rows** (seeded by ETL): `COTS`, `Homegrown`

---

### architecture_types

Reference table for architecture type values found in the CMDB data.

| Column | Type | Nullable | Description |
|--------|------|----------|-------------|
| `arch_id` | TEXT PK | No | UUID v4 |
| `arch_name` | TEXT NOT NULL UNIQUE | No | e.g., `'Client Server'`, `'Platform Host'`, `'Web Based'`, `'N-Tier'`, `'Other'` |

**Note**: Architecture type values are loaded as-is from the CMDB (not normalized to a fixed set). New values encountered in future XLSX exports are added as new rows.

---

### business_processes

Reference table for business process names.

| Column | Type | Nullable | Description |
|--------|------|----------|-------------|
| `process_id` | TEXT PK | No | UUID v4 |
| `process_name` | TEXT NOT NULL UNIQUE | No | e.g., `'Imaging'`, `'Radiation Oncology'`, `'Pharmacy'` |

**Note**: Business process values are loaded as-is (no canonical taxonomy in v1, per A-2). The `'-Not Listed-'` value is loaded as a valid process name; cleanup is deferred post-launch.

---

### companies

Reference table for Baptist Health entities.

| Column | Type | Nullable | Description |
|--------|------|----------|-------------|
| `company_id` | TEXT PK | No | UUID v4 |
| `company_name` | TEXT NOT NULL UNIQUE | No | e.g., `'Baptist Hospital'`, `'BHMG'`, `'South Miami Hospital'` |

---

### etl_runs

Audit trail for every ETL pipeline execution.

| Column | Type | Nullable | Description |
|--------|------|----------|-------------|
| `run_id` | TEXT PK | No | UUID v4 (generated by the ETL pipeline at run start) |
| `run_at` | TEXT NOT NULL | No | ISO 8601 timestamp of run start |
| `xlsx_hash` | TEXT | Yes | SHA-256 of the uploaded XLSX file |
| `records_loaded` | INTEGER | Yes | Count of records successfully written to `applications` |
| `records_skipped` | INTEGER | Yes | Count of records that failed normalization or write |
| `status` | TEXT NOT NULL | No | `'success'` \| `'partial'` \| `'failed'` |
| `error_detail` | TEXT | Yes | JSON array of `{application_name, company, reason}` for skipped records |

## Edge Tables (Graph Layer)

These tables are the source of truth for the networkx DiGraph loaded at FastAPI startup.

### app_uses_type

Many-to-many between applications and application_types.

| Column | Type | Description |
|--------|------|-------------|
| `application_id` | TEXT FK → applications | |
| `type_id` | TEXT FK → application_types | |
| PK | (application_id, type_id) | Composite |

---

### app_has_architecture

Many-to-many between applications and architecture_types.

| Column | Type | Description |
|--------|------|-------------|
| `application_id` | TEXT FK → applications | |
| `arch_id` | TEXT FK → architecture_types | |
| PK | (application_id, arch_id) | Composite |

---

### app_supports_process

Many-to-many between applications and business_processes. This is the primary edge for redundancy cluster detection (Epic 2).

| Column | Type | Description |
|--------|------|-------------|
| `application_id` | TEXT FK → applications | |
| `process_id` | TEXT FK → business_processes | |
| PK | (application_id, process_id) | Composite |

## Full DDL

```sql
-- Enable WAL mode (run after connection open)
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

-- ─────────────────────────────────────────────
-- Node Tables
-- ─────────────────────────────────────────────

CREATE TABLE IF NOT EXISTS applications (
    application_id      TEXT PRIMARY KEY,
    application_name    TEXT NOT NULL,
    company             TEXT,
    publisher           TEXT,
    description         TEXT,
    updated             TEXT,
    last_updated_by     TEXT,               -- PII: store only, never embed/send to AI
    business_owner      TEXT,               -- PII
    td_app_owner        TEXT,               -- PII
    primary_engineer    TEXT,               -- PII
    support_group       TEXT,
    active              INTEGER,
    install_status      TEXT,
    application_url     TEXT,
    portfolio_manager   TEXT,
    application_type    TEXT,               -- 'COTS' | 'Homegrown' | NULL
    architecture_type   TEXT,
    baptist_managed     INTEGER,            -- 1 | 0 | NULL
    business_criticality TEXT,
    business_process    TEXT,
    environment         TEXT,
    active_status       INTEGER NOT NULL DEFAULT 1,  -- 0 = soft-deleted
    content_hash        TEXT                         -- SHA-256(name + description)
);

CREATE TABLE IF NOT EXISTS application_types (
    type_id     TEXT PRIMARY KEY,
    type_name   TEXT NOT NULL UNIQUE
);

CREATE TABLE IF NOT EXISTS architecture_types (
    arch_id     TEXT PRIMARY KEY,
    arch_name   TEXT NOT NULL UNIQUE
);

CREATE TABLE IF NOT EXISTS business_processes (
    process_id   TEXT PRIMARY KEY,
    process_name TEXT NOT NULL UNIQUE
);

CREATE TABLE IF NOT EXISTS companies (
    company_id   TEXT PRIMARY KEY,
    company_name TEXT NOT NULL UNIQUE
);

-- ─────────────────────────────────────────────
-- Edge Tables (Graph Layer)
-- ─────────────────────────────────────────────

CREATE TABLE IF NOT EXISTS app_uses_type (
    application_id TEXT NOT NULL REFERENCES applications(application_id),
    type_id        TEXT NOT NULL REFERENCES application_types(type_id),
    PRIMARY KEY (application_id, type_id)
);

CREATE TABLE IF NOT EXISTS app_has_architecture (
    application_id TEXT NOT NULL REFERENCES applications(application_id),
    arch_id        TEXT NOT NULL REFERENCES architecture_types(arch_id),
    PRIMARY KEY (application_id, arch_id)
);

CREATE TABLE IF NOT EXISTS app_supports_process (
    application_id TEXT NOT NULL REFERENCES applications(application_id),
    process_id     TEXT NOT NULL REFERENCES business_processes(process_id),
    PRIMARY KEY (application_id, process_id)
);

-- ─────────────────────────────────────────────
-- ETL Audit
-- ─────────────────────────────────────────────

CREATE TABLE IF NOT EXISTS etl_runs (
    run_id          TEXT PRIMARY KEY,
    run_at          TEXT NOT NULL,          -- ISO 8601
    xlsx_hash       TEXT,                   -- SHA-256 of uploaded file
    records_loaded  INTEGER,
    records_skipped INTEGER,
    status          TEXT NOT NULL,          -- 'success' | 'partial' | 'failed'
    error_detail    TEXT                    -- JSON array of {name, company, reason}
);

-- ─────────────────────────────────────────────
-- Indexes (query performance)
-- ─────────────────────────────────────────────

CREATE INDEX IF NOT EXISTS idx_applications_type
    ON applications(application_type) WHERE active_status = 1;

CREATE INDEX IF NOT EXISTS idx_applications_company
    ON applications(company) WHERE active_status = 1;

CREATE INDEX IF NOT EXISTS idx_applications_baptist_managed
    ON applications(baptist_managed) WHERE active_status = 1;

CREATE INDEX IF NOT EXISTS idx_applications_name
    ON applications(application_name) WHERE active_status = 1;

CREATE INDEX IF NOT EXISTS idx_app_supports_process_process
    ON app_supports_process(process_id);

CREATE INDEX IF NOT EXISTS idx_app_uses_type_type
    ON app_uses_type(type_id);

CREATE INDEX IF NOT EXISTS idx_etl_runs_run_at
    ON etl_runs(run_at DESC);
```

## Entity-Relationship Overview

```
companies ───── (implied by company field on applications)

application_types ─── app_uses_type ─── applications ─── app_supports_process ─── business_processes
                                              │
                                       app_has_architecture
                                              │
                                       architecture_types
```

**networkx graph representation** (loaded at startup):
- **Nodes**: All rows from `applications` (active_status=1), `business_processes`, `application_types`, `architecture_types`
- **Edges**: All rows from `app_supports_process`, `app_uses_type`, `app_has_architecture`
- **Node type attribute**: Used to distinguish node categories in traversal (e.g., `type='application'` vs `type='process'`)

## Validation Rules

| Field | Rule |
|-------|------|
| `application_type` | Must be `'COTS'`, `'Homegrown'`, or NULL. Any other value → store NULL + warning log |
| `baptist_managed` | `True/False/Yes/No/1/0` (case-insensitive) → 1 or 0. Other values → NULL + warning log |
| String fields | Leading/trailing whitespace stripped before persistence. Empty string → NULL |
| `business_process` | Stored as-is (no normalization). `'-Not Listed-'` is a valid value in v1 |
| `application_id` | UUID v4. Never manually assigned. Preserved across re-ingests by (name, company) lookup |
| `active_status` | Always 1 on new ingest; set to 0 for records absent from new XLSX |
| Duplicate (name, company) | Both records loaded with distinct UUIDs; warning log written for each duplicate |

## ChromaDB Collection (Epic 3 Contract — Established in Epic 1)

The ETL pipeline establishes this contract in `embed.py` even as a stub in Epic 1:

| Field | Value |
|-------|-------|
| Collection name | `"applications"` |
| Document ID | `application_id` (UUID) |
| Document text | `f"{application_name} {description}"` — no PII fields |
| Metadata stored | `application_type`, `business_process`, `baptist_managed` |
| Metadata excluded | All PII fields, `application_url`, `last_updated_by`, `business_owner`, `td_app_owner`, `primary_engineer` |
| Model | `all-MiniLM-L6-v2` (sentence-transformers, CPU) |
| Persistence path | `data/chroma/` (SQLite-backed ChromaDB) |

**Incremental update rule**: On re-ingest, only records where `content_hash` differs from the stored value are re-embedded. Unchanged records retain their existing vectors.
